# PlexonSkills 2.0.0

Stable GitHub repository closure of the accepted PlexonSkills 2.0 premium progression line and Phase 3 performance candidate, plus one cooldown-lifecycle exploit fix discovered during the final source audit.

## Product and progression boundary

PlexonSkills remains PlexonCraft's first-party Core-native RPG progression system with 13 skills, provenance-aware XP routing, active abilities, milestone-derived passives, premium GUI flows, asynchronous leaderboards, PlaceholderAPI, administration tooling, migration-safe Core SQLite persistence, and the public ServicesManager API/event contract.

Canonical XP remains loaded-profile/main-thread authoritative. PlexonCore remains the block-event/provenance and SQLite infrastructure authority.

## Final stability fix

Configured active-ability cooldowns now survive normal player logout/reconnect.

Previously `AbilityRuntime` removed both active and cooldown state on `PlayerQuitEvent`, so disconnecting immediately after activation bypassed the configured 90–120 second cooldown. Stable 2.0 now applies the intended lifecycle:

- active effects end when the player leaves;
- the original cooldown deadline remains authoritative across reconnect;
- cooldown-only owners are aged by the same shared expiration sweep;
- expired offline cooldown state is removed automatically;
- offline cooldown holders do not count as active players;
- explicit administrator cooldown clear and runtime reload behavior remain unchanged.

## Stability architecture retained

- Core-routed block XP with natural/player-placed/unknown provenance policy;
- narrow combat, fishing, acrobatics, repair and alchemy listeners;
- primary-thread XP/profile mutation;
- generation-safe asynchronous profile loading;
- detached logout snapshots and shutdown persistence barrier;
- Core-owned serialized/coalesced SQLite writes;
- schema-2 migration with mandatory pre-2.0 backup and canonical XP fingerprint validation;
- one shared ability expiration coordinator rather than one task per player;
- cached-memory PlaceholderAPI reads;
- asynchronous leaderboard/rank queries;
- atomic runtime candidate reload with rollback.
